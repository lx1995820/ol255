# 球场脉搏

NBA2KOL2 5v5 比赛记录与公开榜单。朋友可以查询选手、查看场均数据、胜率及荣誉预测，并无需登录为选手打分；管理员可以连续录入比赛、筛选、编辑和删除记录。

## 技术与部署

前端使用原生 HTML、CSS、JavaScript 与 Vite，后端使用 Netlify Functions。比赛数据存储在 Netlify Database（托管 Postgres），通过 Drizzle ORM 查询；账户登录使用 `@netlify/identity`。数据库迁移位于 `netlify/database/migrations/`，部署时自动执行，同时一次性导入附件中的 30 条原有比赛记录。后续修改不会重新导入已删除的记录。

网站首页为公开榜单，管理员入口为 `/admin.html`。原有 `/public.html` 地址会跳转到首页。只发布前端构建产物，不发布旧的服务端代码或 JSON 数据文件。

## 首次配置管理员

在 Netlify 项目的 Identity 页面邀请管理员邮箱。管理员打开邀请链接后，在本站设置自己的密码。回到 Identity 用户详情，将该用户的角色设置为 `admin` 并保存，再重新登录。比赛记录的所有写入接口都在服务端检查此角色；普通账户和未登录访客不能修改比赛数据。游客评分不授予比赛管理权限。

建议在 Project configuration → Identity 将注册方式设为 Invite only。本站不提供公开注册入口，也不使用共享默认密码。管理员可以在登录页申请密码重置。邀请及重置链接回到首页或后台页时均可处理。

## 本地运行

需要 Node.js 22.23 或更新版本，以及已关联此项目的 Netlify CLI。安装依赖后使用 Netlify 本地环境，以便模拟 Functions、Identity 和数据库连接：

```sh
npm install
netlify link
npm run dev:netlify
```

打开 `http://localhost:8889/`。部署构建命令为 `npm run build`，发布目录为 `dist`。本次适配没有运行本地构建或开发服务器，由平台流水线安装并验证。

## 数据与维护

`db/schema.ts` 定义比赛记录、历史留言、选手评分、赛季和月度荣誉表。修改表结构后运行 `npm run db:generate -- --name 描述性英文名称`，提交生成的迁移文件；已应用的迁移不可修改或删除。不要在生产环境依赖本地 JSON 或内存来保存比赛记录或评分。公开榜单每 30 秒检查更新，切回页面时也会刷新；网络错误会保留已显示的数据并提供重试提示。

月度荣誉基于当前月份的已录入统计，是预测而非官方奖项。每位选手每场仍是一条统计记录，个人场均、胜率及个人参赛次数包含所有记录。首页和后台的“已分配场次”按比赛日期与场次编号去重统计，同场多个选手不会重复计数；缺少编号的旧记录不计入此总数，并单独显示待分配记录数量。

场均榜仅纳入历史累计满 20 场的选手，各指标从高到低展示前 7 名，不受赛季筛选影响。单场榜按每位选手五项最高值分别展示前五，不设场次门槛。未满 20 场的选手仍可搜索、评分和参与单场纪录。独立锦标赛场均榜按本届赛事出场数计算，同样要求满 20 场。

公开首页的月度 MVP、DPOY 及得分、篮板、助攻、抢断、盖帽王均展示前五位候选，附带本月指标和参赛次数；不足五人时展示全部合资格选手。本月须满 20 场才可参与任何月度奖项与最佳阵容，无合资格选手时显示空状态。MVP 评分（满分 100）为本月胜率百分数乘以 60%，加上场均得分、篮板、助攻之和相对于本月合资格选手最高综合值的百分数乘以 40%；最高综合值为零时数据部分计零。DPOY 按场均抢断、盖帽与篮板之和排序，最佳防守阵容使用相同评分，其他单项奖按对应场均数据排序。同分时优先参赛场次更多者，再按绰号排序。

## 游客评分

榜单、比赛记录和搜索结果均提供五星评分入口，支持 0.5 星步进和可选的 120 字评语。月榜显示当月平均分；累计榜显示所有月份的评分算术平均值，参与人数按设备去重。星级按最近半星显示，数字保留一位小数。

评分存储在 Netlify Database，以浏览器设备标识、选手和北京时间自然月去重；同一设备当月重新提交会修改原记录。无需登录，但清除浏览器数据、更换设备或人为更换标识可绕过去重，不能保证严格防刷。历史留言只读保留，不计入评分。评分记录展示最近 100 条，历史留言可分页查看。

## 场次录入与查询

管理员录入统计的顺序为：得分、篮板、助攻、抢断、盖帽。先选择比赛日期，再选择已有场次或“新增场次 / 自定编号”，例如 2026 年 10 月 9 日第 1 场、第 2 场。场次编号按日期独立管理，范围为 1–10000。

同场的不同选手选择同一日期和编号。保存后表单保留当前日期和场次，清空选手与统计输入，以便继续录入同场其他选手；“录入下一场”切换到当天已用编号和当前编号之后的下一编号。新增编号随第一条选手记录保存，不额外创建空场次计划。同一选手在同一天同一场只能保存一条记录，重复录入会提示编辑原记录。

原有记录没有可靠场次信息，因此新增迁移保留其数据并将场次留空，前后台显示“场次待分配”。管理员可逐条编辑旧记录，选择正确场次后保存；编辑其他数据时也可暂时保留待分配状态，不会自动猜测历史编号。

公开首页新增比赛明细，与后台一致显示日期、场次、选手和五项统计，支持日期与场次筛选；公开首页的绰号查询同时筛选明细。数据沿用每 30 秒自动同步与手动刷新，后台场次修改会同步到公开页面。


## 截图批量导入

后台支持每批最多 20 张红字昵称比赛截图，每张不超过 8MB；浏览器压缩后逐张调用管理员专用 `/api/admin/recognize`，通过 Netlify AI Gateway 的 GPT-5.2 提取红字昵称、五项数据和胜负。不保存截图。每张截图共用一场比赛，按起始场次递增；管理员必须核对日期、场次及所有数据后，在可编辑表格中确认提交。不确定内容保留空白，未知昵称需修正为已有选手；新选手先通过单条录入创建。失败图片可单独重传，已成功识别的行仍保留核对。

`POST /api/admin/import` 接收 `{ rows, confirm: true }`，最多 200 条。所有行经过服务器校验后，在一条数据库 INSERT 内写入，任何重复行都会让整批失败，避免部分成功。识别和导入均要求 Identity 的 `admin` 角色及同源请求。

## 赛季、荣誉与社区统计

后台赛季管理可手动命名并重开赛季，每月 8 日显示提醒。以北京时间操作当天为新赛季起点，当天已有记录计入新赛季，每天最多开启一次；旧赛季结束时间取下一赛季起点。首页默认当前赛季，可切换历史总榜、初始赛季及各赛季；记录始终保留。月度预测和荣誉按全站自然月，不受赛季筛选影响。

每天北京时间 00:05 的定时任务将已结束自然月的奖项写入荣誉表；首页读取也会补齐漏归档月份。每月只写一次，后续补录、修改和删除不会改写已归档荣誉。获奖项目包含 MVP、DPOY、五项单项王及最佳一二阵、防守一二阵，参赛门槛均为该月 20 场；旧归档展示时根据现有比赛记录过滤不足 20 场的选手。

选手标签按页面所示规则自动计算，最多五个，按用户提供的规则顺序优先展示。排名类标签满 8 场参与，同分按场次、昵称稳定排序；内线大闸按累计抢断加盖帽，死亡缠绕按累计抢断，三双猛男按场均得分篮板助攻之和，孤胆英雄按场均助攻不超过 2 且得分大于 10 判定。历史留名包含并列最高纪录，关键先生要求同时有胜场和负场。

最强搭子、三巨头和卧龙凤雏至少共同出场 3 场，比较共同胜率，再比较成员人均得分篮板助攻之和。一生之敌按同场对手计算，相比个人整体胜率下降最多的前三组入榜。仅使用有场次编号的记录，忽略超过十人、重复选手或单侧超过五人的异常场次。25 分俱乐部包含所选范围内单场至少 25 分选手。顶部快讯仅从历史真实出场、纪录和胜率生成，不虚构临近破纪录事件。


### 独立锦标赛与关系档案

后台“独立锦标赛管理”可新建一天举行的赛事，选择“进行中”保存后持续补录。点击“增加一场”生成两队各五名选手的数据行，填写场次、昵称、胜负和五项数据；昵称允许新选手直接加入。每行代表一名选手在一场比赛的表现，删除行需保存后生效。当前支持每届最多 1000 条选手记录。

冠亚季军阵容各按每行一人填写，MVP 由管理员指定。结束赛事前，服务器要求每场胜负双方各五人、前三名各五人且不重名，荣誉人选必须已参加本届赛事。赛事修改带版本检查，避免多人编辑覆盖。重新加载或切换赛事会放弃尚未保存的编辑。

首页锦标赛分区保留历届数据，可切换查看五项场均前三、出场数、前三名阵容与 MVP。出场至少 20 场才可进入锦标赛场均排名，按场均、出场数、昵称依次排序。全部锦标赛数据独立保存，不影响日常统计、赛季、关系和自然月荣誉。

日常关系档案每类展示前五，共同参赛门槛提高至十场，搭子和三巨头使用带十场中性先验的平滑胜率减少小样本影响。宿敌需要交手和其他对局各满十场，以其他对局的平滑胜率为对照；新增共同出场最多的默契老搭档及胜率最接近五成的势均力敌。截图批量导入接受核对后的新昵称，已有选手仍需保持相同拼写以合并统计。
